証明できる指摘だけを出す仮説駆動セキュリティアセスメントを Claude Code Skill にした

はてなブックマーク（テクノロジー）2026年9月2日

筆者は以前に作ったレイヤー別の検出パターン集「security-audit」を運用するうち、「どこを見るか」と「どう結論づけるか」は別の技術だと気づき、後者を担う新しいスキル「security-assessment」を作った。

AIにセキュリティレビューをさせると、到達性も悪用可能性も確かめずにパターンだけで脆弱性だと報告する偽陽性と、見ていない箇所を何となく大丈夫と済ませるサイレントな見落としという2つの壊れ方をする。

新しいスキルの中心にあるのは3つの仕組みで、攻撃者の能力について反証可能な1文を仮説として立て、証拠を探す前にそれを否定する条件（falsifier）を先に書くことで、パターンマッチによる早合点を止める。

確定できないものは勝手に安全とみなさずUNKNOWNとして登録し、UNKNOWNが悪用経路上に残る限りその指摘はCONFIRMEDに昇格できないよう機械的に強制する。

証拠にはE1からE6のグレードを設け、ツール出力のみのE5や思い込みのE6は単独では指摘にできず、重大度もCVSS単体ではなく技術影響・悪用可能性・ビジネス影響・露出の4軸を1〜4で採点して算出する。

実際の運用ではオーケストレーターと4つのサブエージェントで分担し、指摘への昇格はオーケストレーターだけが行った結果、30件中20件がノイズという状態から本物6件へと指摘の質が変わった。
